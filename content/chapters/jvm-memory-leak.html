这一章要解决的生产问题

网关服务堆用量平稳，容器内存却每周稳定上涨，最终被 K8s OOMKilled。jmap 看堆干干净净——问题根本不在堆里。

写作中

本章正在按样板章结构写作（场景 → 判断框架 → 回到工位 → 面试怎么答 → 追问链）。计划覆盖的判断点：

  • OOM 的分类学：堆 / 元空间 / 直接内存 / 栈 / 容器 cgroup——先分清是哪种，再谈定位
  • DirectByteBuffer 为什么不受 GC 直接管理（引用计数 vs GC 感知），Netty PoolArena 与 -XX:MaxDirectMemorySize 的关系
  • 诊断链路：NMT（jcmd VM.native_memory）、pmap、按段排除（glibc arena / 线程栈 / CodeCache）
  • 被否决选项的胜场：“重启大法”作为止血手段的正当性与限度
  • 面试分层信号：能说出“OOM 不一定是堆”是分水岭，能讲 NMT baseline 对比是加分
