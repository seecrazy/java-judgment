# Java 高级判断力：从能写到敢做决定

一个部署在 GitHub Pages 上的开源技术书项目。核心主张：**高级 Java 面试筛的不是"知不知道"，是"为什么选这个、为什么不选那个、出过什么问题"——这恰好也是工作中拉开差距的能力。** 所以每个场景同时给两样东西：工作中的决策清单，面试里的回答框架。

## 差异化定位

不做知识点大全（advanced-java / JavaGuide 已经足够好）。每章只做一件事：把"工作中的判断"和"面试里的表达"之间的那层纸捅破——**你在工作中做过的那个决策，怎么讲才能被认可为"高级"**。

## 内容结构

五条主线 × 21 章（规划量），每章固定五节，顺序不可变：

**工作场景 → 判断框架（五步判断法）→ 回到工位（动手）→ 面试怎么答 → 追问链（折叠，先自己答 10 秒）**

动手放在面试话术之前：扛得住追问三连的答案，只能来自你真的跑过一遍。

| 主线 | 面试官追问 | 章数 |
|---|---|---|
| 一 · JVM 与性能 | 你真的调过吗？ | 5 |
| 二 · 并发与线程池 | 参数怎么定的？ | 4 |
| 三 · 缓存与分布式 | 为什么不用另一个？ | 5 |
| 四 · MySQL | 这条 SQL 为什么这么跑？ | 3 |
| 五 · 系统设计 | 日活涨 100 倍怎么办？ | 4 |

当前进度：**3 篇全文样板章**（G1 Full GC 排查 / 线程池拒绝策略 / 缓存击穿），其余 18 章已规划（每章有场景预告 + 判断点大纲）。铺开节奏见 [WRITING_GUIDE.md](WRITING_GUIDE.md)。

## 站点形态

- **双入口**：入口 A 按面试轮次（一面/二面/系统设计面），入口 B 按工作场景（性能/并发/缓存/数据库/架构），指向同一批章节
- 每章顶部标注面试信号强度 + 整理时间 + 适用公司类型 + 工作触发场景
- 全文搜索（首页输入框，按 `/` 聚焦）、深色模式、移动端适配
- mermaid 决策树 / 表格清单直接嵌在正文里

## 快速开始

```bash
python3 -m pip install pytest   # 仅测试需要；构建只用标准库
python3 build.py                # 生成 site/
python3 -m http.server -d site 8000   # 本地预览 http://127.0.0.1:8000
python3 -m pytest -q            # 58 项内容校验
```

注意：本地预览需联网加载 mermaid（CDN）；离线时图不渲染，正文不受影响。

## 目录结构

```
content/
  lines.json            # 五条主线（含版本现状卡）
  chapters/*.html       # 章节 = chapter-meta(JSON) + 正文片段
template/               # 页面模板 + 样式/脚本（构建时拷入 site/assets）
build.py                # 纯标准库构建：页面组装 + 搜索索引 + 元数据校验
test_content.py         # 内容校验：结构、编辑守则、断链、构建产物
.github/workflows/      # Pages 部署（pytest 作为门禁）
site/                   # 构建产物（不入库）
```

## 部署

推送到 `main` 即自动部署 GitHub Pages：workflow 先跑 pytest（内容校验门禁），再构建 `site/` 并发布。仓库需在 Settings → Pages 选择 "GitHub Actions" 作为来源。

## 贡献：让追问链不过时

面经会漂移。如果你在真实面试里被追问了书里没有的问题，欢迎提 PR 把它补进对应章节的追问链（格式：追问 + 考察意图 + 过关标准）。这是这个项目保持不过时的机制。
