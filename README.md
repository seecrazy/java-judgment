# Java 高级判断力：从能写到敢做决定

> 每个场景，同时给你两样东西：**工作中知道怎么选，面试时知道怎么说。**

高级 Java 面试筛的不是"知不知道"，是"为什么选这个、为什么不选那个、出过什么问题"。这恰好也是工作中拉开差距的能力——所以这本书不做知识点大全（[advanced-java](https://github.com/doocs/advanced-java)、JavaGuide 已经足够好），只做一件事：**把"工作中的判断"和"面试里的表达"之间的那层纸捅破。**

- **适合谁**：3~8 年 Java 工程师——准备社招/跳槽，或想在技术评审里把方案讲得让高级/资深岗认可的人。
- **不适合谁**：还在背"HashMap 底层原理"阶段的同学，先把基础题库过完再来，这里的每一章都假设你会写、缺的是敢做决定。

## 这本书怎么读

每章固定五节，顺序经过刻意设计：

```
工作场景 → 判断框架 → 回到工位（动手）→ 面试怎么答 → 追问链（折叠自测）
```

- **动手在话术之前**：扛得住面试官追问三连的答案，只能来自你真的跑过一遍。"回到工位"给的都是明天上班就能执行的动作——一条命令、一份盘点清单、一句要问业务的话。
- **五步判断法**贯穿全书：约束 → 选项 → 代价 → 押注 → 复盘。读 21 章等于把同一套决策程序示范 21 遍，带走的是程序本身。
- **追问链默认折叠**：先自己心里答 10 秒再展开。追问才是高级面试真正的战场，每个追问都标注了考察意图和过关标准。
- **站点双入口**：入口 A 按面试轮次（一面/二面/系统设计面），入口 B 按工作场景（性能/并发/缓存/数据库/架构）——同一批章节，两种导航。

技术结论全部标注版本边界（JDK 8~25、MySQL 8.0、Redis 7 生态），拒绝无版本的普适论断。

## 样章尝鲜

同一个问题，八股答案和这本书的答案差在哪——「索引选型与慢查」的 60 秒示范：

> "1.2 亿行订单表，后台列表 LIMIT 10000000, 20 跑 8.2 秒拖垮从库。我先 explain：type=ref、Extra=Using index——**索引已经最优**，问题是 offset 要产生并丢弃 1000 万行，这不是索引能救的。所以答案是业务改写：列表改游标，6ms 返回。加宽索引我评估过没做——为日均 200 次的后台查询，让主库 4500 写 QPS 背 12 个字段的写放大，不划算。事后还删了 3 个没人用的索引，主库写入 P99 从 45ms 降到 28ms。"

三句话里有数字、有押注、有一句"没做 X，因为 Y"——这正是面试官在听的，也是 AI 生成的答案给不了的。完整方法论见站点的「五步判断法 → 别背 AI 答案」一节。

## 快速开始

```bash
python3 -m pip install pytest   # 仅测试需要；构建只用标准库
python3 build.py                # 生成 site/
python3 -m http.server -d site 8000   # 本地预览 http://127.0.0.1:8000
python3 -m pytest -q            # 130 项内容校验
python3 check_chapter.py content/chapters/<某章>.html   # 单章结构自查
```

注意：本地预览需联网加载 mermaid（CDN）；离线时图不渲染，正文不受影响。

## 项目结构

```
content/
  lines.json            # 五条主线（含版本现状卡）
  chapters/*.html       # 21 章 = chapter-meta(JSON) + 正文片段
template/               # 页面模板 + 样式/脚本（构建时拷入 site/assets）
build.py                # 纯标准库构建：页面组装 + 搜索索引 + 元数据校验
test_content.py         # 内容校验：结构、编辑守则、断链、构建产物（130 项）
check_chapter.py        # 单章自查工具（写作时用）
WRITING_GUIDE.md        # 章节结构与六条编辑守则（想贡献内容先读它）
.github/workflows/      # Pages 部署（pytest 作为门禁）
site/                   # 构建产物（不入库）
```

## 部署

推送到 `main` 即自动发布 GitHub Pages：workflow 先跑 pytest（内容校验门禁），再构建 `site/` 并发布。仓库需在 Settings → Pages 选择 "GitHub Actions" 作为来源。

## 贡献：让追问链不过时

面经会漂移，但这个项目有自我更新机制：如果你在真实面试里被追问了书里没有的问题，欢迎提 PR 把它补进对应章节的追问链（格式：追问 + 考察意图 + 过关标准，参照任意一章的 `<details>` 写法）。新增或改写章节请先读 [WRITING_GUIDE.md](WRITING_GUIDE.md)——六条编辑守则里最重要的是这一条：**被否决的方案必须写清它在什么场景下是对的。**
